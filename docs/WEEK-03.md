# Неделя 3 · 21–25.09 — Python, git, первая программа на сервере

Первая неделя ежедневного формата и самая рискованная в программе: **7 студентов из 11
не знают ни одного языка**, а к пятнице у каждой команды должна работать программа
на школьном сервере.

**Цель недели:** не «пройти основы Python», а довести три команды до состояния, когда
у каждой есть репозиторий, коммиты от всех участников и запускающаяся на сервере программа.
Язык даётся ровно в объёме, который для этого нужен.

> **Исключение из правила про 15 минут.** В обычную неделю мини-тема занимает не больше
> четверти часа. На этой неделе объяснение занимает 30–40 минут, потому что мы учим язык.
> С недели 4 возвращаемся к 15 минутам.

---

## Главное упрощение недели

Все три отобранных проекта в первой версии сводятся к одной и той же форме:

```text
  список  →  фильтр  →  печать
```

- учёт ПК: список машин → какие включены → печать;
- Lost&Found: список находок → за какую дату → печать;
- задания/расписание: список заданий → на сегодня → печать.

Значит, **одно объяснение работает на все три команды**, а различаются только данные.
Это и есть тот случай, когда можно учить язык на настоящей задаче, а не на абстрактных примерах.

## Понедельник 21.09 — первая своя программа

**Цель дня: у каждого на экране работает программа, которую он написал сам.**

| Время | Что |
|---|---|
| 11:00–11:40 | Как устроено: файл с текстом → интерпретатор → результат. Запуск `python file.py`. Без теории про типы и память |
| 11:40–13:00 | Каждый пишет программу: спрашивает имя, здоровается. Дальше — просит два числа, печатает сумму. Ошибки неизбежны и это материал дня: опечатка, отступ, кавычки |
| 13:00–14:00 | Перерыв. Командам без заказчика — идти искать |
| 14:00–15:00 | Переменные, строки, числа. Задача: программа считает что-нибудь из их проекта (сколько машин в списке, сколько находок) |

**Выход дня:** каждый студент хотя бы раз увидел, как его собственный код что-то напечатал.
Это важнее пройденного объёма.

**Группа B в это время:** идут с тобой на ревизию сервера — `python3 --version`, git, ssh, порт,

## Вторник 22.09 — программа принимает решения

**Цель дня: программа делает разное в зависимости от данных.**

| Время | Что |
|---|---|
| 11:00–11:40 | `if` / `else`, сравнения. Список и `for` — минимально, без методов списков |
| 11:40–13:00 | Каждая команда описывает свои данные списком прямо в коде (машины, находки, задания) и печатает их по одному |
| 13:00–14:00 | Перерыв, окно заказчика |
| 14:00–15:00 | Фильтр: печатать не всё, а подходящее. «Только включённые», «только за сегодня» |

**Выход дня:** у каждой команды есть файл, который печатает отфильтрованный список.
Это уже скелет их продукта — сказать это вслух.

**Группа B:** им та же задача скучна. Дать вторую: функция, которая читает данные из файла,
чтобы список не был вшит в код. К четвергу это понадобится всем — они принесут решение
остальным.

## Среда 23.09 — git, потому что вчера что-то потерялось

**Цель дня: у каждого локальный репозиторий с историей.**

К среде накопится три дня правок, и кто-нибудь уже сломает работавший файл. Этого не надо
избегать — на этом строится день.

| Время | Что |
|---|---|
| 11:00–11:40 | Зачем история. `git init`, `add`, `commit`, `log` |
| 11:40–12:30 | Каждый делает репозиторий из своего файла и 3–5 коммитов по ходу правок |
| 12:30–13:00 | **Упражнение «сломай и восстанови»**: испортить файл намеренно, вернуть версию из истории. Пока не сделает сам — день не закрыт |
| 13:00–14:00 | Перерыв, окно заказчика |
| 14:00–15:00 | `diff`, `status`, что такое рабочая копия. Правило сообщений коммита: `add filter by date`, а не `fix` |

**Выход дня:** каждый восстановил файл из истории своими руками. Это и есть момент, после
которого git перестаёт быть ритуалом.

**Не вводить на этой неделе:** ветки, merge, конфликты. Их боль наступит на неделе 4.

| Время | Что |

должна запомниться.

**Группа B:** готовят деплой к пятнице — как положить файл на сервер и запустить. Пусть напишут

## Пятница 25.09 — сервер, демо, ретро

**Цель дня: программа каждой команды запускается на школьном сервере.**

| Время | Что |
|---|---|
| 11:00–11:30 | Что значит «на сервере»: ssh, чужая машина, почему «у меня работало» не аргумент |
| 11:30–13:00 | Деплой по инструкции группы B. Каждая команда доводит свою программу до запуска на сервере |
| 13:00–14:00 | Перерыв |
| 14:00–14:40 | **Демо заказчику.** Показывает не тимлид, а тот, кто меньше всех выступал. Показываем запуск, а не рассказ |
| 14:40–15:00 | Ретро: что помогло, что мешало, что меняем на следующей неделе — ровно один пункт. Письменно, в репозиторий |

**Выход недели:**

- [ ] Три репозитория, в каждом коммиты от всех участников
- [ ] Три программы запускаются на школьном сервере
- [ ] Каждый студент хотя бы раз восстановил файл из истории git
- [ ] `docs/INFRA.md` написан
- [ ] Заказчик видел работающий запуск
- [ ] Ретро в репозитории

## Роль группы B

Шесть человек уже знают bash, ssh, сети, часть — Python и git. Держать их на «напиши сумму двух
чисел» — быстрый способ их потерять. У них своя линия:

| День | Задача группы B |
|---|---|
| Пн | Ревизия сервера вместе с преподавателем → `docs/INFRA.md` |
| Вт | Чтение данных из файла — решение, которое в четверг понадобится всем |
| Ср | Помогают соседям по столу с git; сами разбирают `.gitignore` |
| Чт | Пишут инструкцию по деплою |
| Пт | Ведут деплой, остальные идут по их инструкции |

Сказать им это прямо в понедельник: они не «сильные, которым скучно», а те, на ком держится
инфраструктура. Ответственность удерживает лучше, чем дополнительные задачи.

## Если пойдёт не так

| Ситуация | Что делать |
|---|---|
| К среде половина не написала ни одной работающей программы | Остановить продвижение по темам. Git переносится на четверг, скелет — на следующую неделю. Лучше трое умеющих, чем одиннадцать посмотревших |
| На сервере не оказалось Python или доступа | Пятница проводится на localhost, деплой переносится на неделю 4. Это не катастрофа, но `INFRA.md` тогда становится задачей №1 |
| Группа B убежала далеко вперёд | Перевести их в менторы официально: у каждого 2–3 подопечных. Объяснить другому — это и есть их обучение на этой неделе |
| Кто-то принёс код, сгенерированный AI | Правило то же, что и дальше: объясни каждую строку своими словами. Не может — код не едет. Проговорить это в понедельник, а не в пятницу |
| Не хватает компьютеров | Работа парами, и это не компромисс: пара за одним экраном учится быстрее, чем двое поодиночке |
