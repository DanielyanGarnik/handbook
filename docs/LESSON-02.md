# Занятие 2 — Брейншторм и выбор проектов

Неделя 2 по [сжатому плану](ROADMAP.md#1a-сжатая-версия-на-8-недель-12-студентов).
Длительность: 90 минут.

**Цель занятия:** из сданных болей получить 3 проекта, 3 команды и у каждого проекта — **имя
живого заказчика**. Не «идею», не «тему», а имя человека, с которым можно поговорить.

---

## Исходные данные

Сдали **5 из 12**. В пяти работах — 14 болей, которые сводятся к трём кластерам и двум одиночкам
(разбор: приватный репозиторий `submissions`). Материала для отбора хватает.

Два факта, которые определяют сценарий занятия:

| Факт | Следствие для урока |
|---|---|
| Заказчика не назвал **никто** из пяти | Это главная тема занятия, а не побочная |
| Ник на GitHub прислал **1 из 5** | Собираем ники в классе, иначе неделя 3 встанет |
| Не сдали 7 человек | Нужен вход без штрафа, иначе они выключатся совсем |

## Тайминг

### 0:00–0:10 — Что дали пять работ

Показать результат, а не хвалить процесс: 5 работ → 14 болей → 3 кластера. Три разных человека,
не сговариваясь, описали одну и ту же проблему — **вот это и есть сигнал**, в отличие от идеи,
которая понравилась одному.

Отдельно зачитать формулировку из работы 4: «проблема не в одном потерянном кабеле, а в том,
что нет ответа на три вопроса: где оно, кто взял, свободно ли». Это образец, который стоит
показать всем.

Не устраивать разбор ошибок по именам. Общие провалы — разбираем как общие.

### 0:10–0:25 — Группировка карточек

Карточки перемешаны и розданы. Класс сам группирует их на доске. Тем, кто не сдал, —
пустые карточки: «напиши свою боль сейчас, 5 минут, по тем же пяти вопросам».

Задача ведущего: не подсказывать готовые кластеры. Если класс сгруппирует иначе и объяснит
почему — их группировка правильнее.

### 0:25–0:40 — Главный урок: кто заказчик

Вопрос в лоб: **«назовите имя человека, который скажет, что ему это нужно»**.

Пять работ из пяти этого не сделали — сказать честно и без упрёка: это самая частая ошибка
и во взрослых командах тоже. Дальше показать, к чему это ведёт: без заказчика невозможно понять,
решена ли проблема, и в конце программы нечего поддерживать.

Если разговор с учителем информатики состоялся — привести как живой контрпример: вот боль,
вот человек, вот его слова.

По каждому кластеру на доске дописать строку: **кто этот человек?** Где имени нет — кластер
помечается как незакрытый.

### 0:40–0:55 — Сжатие

Каждая группа берёт свой кластер и отвечает письменно на два вопроса:

1. Что можно сделать за две недели так, чтобы этим уже пользовались?
2. Чего в первой версии НЕ будет — 3–5 пунктов с «потому что»?

Это студенты уже умеют: сжатие — единственная часть ДЗ, которую сделали все пятеро. Здесь они
будут выглядеть успешными, и это нужно для следующего шага.

### 0:55–1:15 — Выбор трёх проектов и команды

Не голосование большинства. Критерий отбора на доске, идём по списку:

| Критерий | Проверка |
|---|---|
| Есть имя заказчика | Можно позвать в класс |
| Влезает в две недели | Первая версия |
| Python, школьный сервер | Проверено на неделе 0 |
| Без персональных данных | — |
| Есть 3–4 человека, готовых это делать | Руки подняты |

Проект берётся, только если выполнены **все** пункты. Кластер без заказчика в работу не идёт —
но и не выбрасывается: помечается `parked`, вернёмся, когда заказчик найдётся.

**Как собирать команды** (см. [TEAM-SKILLS.md](TEAM-SKILLS.md)). Команды 3–4 человека, и в каждой
должны оказаться двое:

- **тот, кто умеет git и доводит до сервера** — из группы B;
- **тот, кто знает язык** — Python или C++.

Это может быть один и тот же человек. Собирать по интересам нельзя: если «админы» окажутся
в одной команде, а «дизайнеры» в другой, одна уедет вперёд, а две встанут на первом же деплое.

Отдельно сказать вслух, пока не разошлись: **язык программы — Python**, и учить его будем вместе
с git, прямо на первой задаче. Те, кто знает C++, освоят Python быстрее всех и станут в своих
командах теми, к кому идут с вопросами. Это роль, а не понижение — иначе решение прочитается
как обесценивание их навыка.

Роли (тимлид, релиз-менеджер, дежурный по багам) назначаем на следующем занятии, не сейчас.

### 1:15–1:25 — GitHub

Лист с никами по классу. У кого нет аккаунта — заводят прямо сейчас с телефона, это 3 минуты.
Без этого неделя 3 не начнётся.

Здесь же объявить **конвенцию формата**: начиная с ДЗ-2 работы сдаются только в `.md`.
Git для этого не нужен — заполнить можно в чате, шаблон дадим текстом. Сказать честно, зачем:
пять форматов в ДЗ-1 стоили лишнего часа на приёме, и это тот случай, когда правило дешевле
программы, которая бы их конвертировала.

### 1:25–1:30 — ДЗ №2

Выдать [HOMEWORK-02.md](HOMEWORK-02.md) — «Найди заказчика». Объяснить в одном предложении:
на следующем занятии у каждого проекта должно быть имя, цитата и согласие живого человека.

## Если пойдёт не так

| Ситуация | Что делать |
|---|---|
| Не нашлось заказчика ни для одного кластера | Не выбирать проекты сегодня. Занятие превращается в «идём и находим»: список людей в школе, кто к кому идёт, дедлайн — завтра. Лучше потерять день, чем 8 недель строить никому не нужное |
| Класс хочет четвёртый проект | Нет. Три команды — это три проекта, которые ты успеешь вести |
| Сильная идея, но нет желающих | `needs-owner`, в инбокс. Не навязывать |
| Пришли только те же пятеро | Занятие проводится в том же формате, но команды по 2 человека и **два** проекта, не три |
| Спорят и не могут выбрать | Решает наличие заказчика. Это не вкусовой критерий, он снимает спор |
