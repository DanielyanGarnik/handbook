# Стек студентов — срез на старте

Источник: доска «Specialization», фото с занятия 17.09.2026. Студенты 2 и 3 курса, те, кто пойдёт
в команды. На доске 11 человек, разбитых на две группы по уровню и направлению.

Здесь — **обезличенный срез**. Именная привязка «кто что умеет» в публичный репозиторий
не выносится: это персональные данные несовершеннолетних.

---

## Группа A — креатив и базовая работа с машиной

Примерно 5 человек.

| Область | Инструменты |
|---|---|
| Видео и звук | CapCut, работа со звуком (у двоих) |
| Графика и дизайн | Figma, Photoshop, Illustrator, GIMP, рисование |
| Терминал | bash (базовый) |
| Прочее | печать / принтер, ASCII-графика, Minecraft, FPS-игры |

## Группа B — системное администрирование и разработка

Примерно 6 человек.

| Область | Инструменты |
|---|---|
| Терминал | bash (продвинутый), vim, nano |
| Сети | networking, SSH |
| Разработка | Python (у части группы, не у всей), git, CSS |
| Инфраструктура | Docker, Cloudflare, Postfix, выпуск SSL-сертификатов |
| Редакторы | VSCode |

> Неуверенно прочитанные позиции: пометка «class» / «2 class» рядом с рисованием и сокращение
> после «Networking». Если это существенно — поправь.

## Что из этого следует

### 1. Языка нет у большинства класса

Реальная картина по языкам — не «Python против C++», а куда более неудобная:

| | Сколько человек из 11 |
|---|---|
| Знают C++ | 2–3 |
| Знают Python | 2–3 |
| **Не знают ни одного языка** | **5–7** |

Программа с самого начала исходила из того, что студенты «пишут на Python и C++». Это верно
для меньшинства. Для большей части класса язык — не инструмент, который у них уже есть,
а предмет обучения.

**Решение: единственный язык программы — Python.** Он проще для старта и изучается вместе с git,
на первой же задаче (walking skeleton на неделе 3), а не отдельным блоком «сначала теория, потом
проект» — отдельной недели на это при сроке в 8 недель просто нет.

C++ в проектах не используется, хотя 2–3 человека им владеют. Причина не в языке: один стек —
это одна среда, одна инструкция по деплою на школьный сервер и работающая взаимопомощь между
командами. При одном преподавателе и восьми неделях два стека не ведутся.

Носителям C++ это надо сказать прямо и в правильной рамке: они освоят Python быстрее всех
и станут в своих командах теми, к кому идут с вопросами. Это роль, а не понижение.

### 2. Git есть только у группы B

Это прямо отвечает на вчерашний вопрос про приём работ через Pull Request: **примерно половина
класса не сможет сдавать через PR ни на неделе 3, ни позже без отдельного обучения.**

Следствия:

- конвенция «сдавать только в `.md`» вводится **сейчас**, она не требует git — заполнить файл
  можно в чате или в веб-интерфейсе;
- PR-валидатор из [карточки преподавателя](https://github.com/RealSchoolPool/submissions) едет
  на группе B, а для группы A нужен второй вход — тот самый чат-бот, который был помечен `parked`.
  Он перестал быть запасным вариантом и стал обязательным;
- git на неделе 3 придётся давать как отдельную тему, а не «между делом».

### 3. Уровень группы B выше, чем я закладывал

Docker, Cloudflare, Postfix, выпуск SSL — это не школьный уровень, а уровень человека, который
уже что-то администрировал. Два следствия:

- **деплой на школьный сервер перестаёт быть риском** и становится сильной стороной. Фазу
  Release можно планировать смелее;
- этих людей нельзя держать на задачах уровня «напиши функцию» — им нужна инфраструктурная
  ответственность (релиз-менеджер, дежурный по багам, настройка CI), иначе они выключатся
  из процесса от скуки.

### 4. Веб под вопросом

Есть CSS, но ни HTML, ни JavaScript на доске не названы. Идеи вида «простой сайт»
(Lost&Found, учёт оборудования) реалистичны только силами группы B и только как очень простая
страница. Для группы A веб-фронтенд — это обучение с нуля, а не применение навыка.

### 5. Команды нужно смешивать, а не собирать по интересам

Главный вывод для формирования команд. Если собрать «дизайнеров» и «админов» отдельно, одна
команда уедет вперёд, а две встанут на первом же деплое.

**Правило: в каждой команде должны оказаться двое** —

- тот, кто умеет **git и деплой** (группа B);
- тот, кто знает **язык** — Python или C++.

Это может быть один и тот же человек, и часто будет им. Остальные — из группы A, на них ложится
всё, что касается того, как продукт выглядит и объясняется.

При 11–12 студентах и трёх командах оба ресурса дефицитны и делятся почти без запаса:
6 человек группы B — как 2 / 2 / 2, носители языка (4–6 человек) — так же. Команда, в которой
не оказалось ни одного из двух, встанет на первой же неделе разработки.

### 6. Навыки группы A не декоративны

Соблазн считать CapCut и Figma «несерьёзным» стеком. Но в программе есть места, где это ровно
то, что нужно:

- Demo Day на неделе 8 — запись и монтаж демо;
- README и инструкции для пользователей — оформление и скриншоты;
- макет интерфейса до того, как написан код, — дешёвый способ спорить об интерфейсе;
- презентация проекта заказчику.

Это стоит сказать вслух на занятии: иначе половина класса будет считать, что они здесь
на вторых ролях.

## Чего на доске нет

Зафиксировано для честности — это то, чему придётся учить с нуля или обходить:

- **Python у большинства** — знают 2–3 из 11, учим остальных с нуля;
- **HTML / JavaScript** — не названы;
- **тестирование** в любом виде;
- **CI** (GitHub Actions и аналоги);
- **работа с базами данных**;
- **английский** — не обсуждался, а он нужен для коммитов и issue.

Отдельно: **C++ на доске есть** (2–3 человека), но в программе он не используется — см. пункт 1.

Первые два пункта меняют выбор проектов, остальные — это программа обучения на недели 3–8
по таблице [«боль → инструмент»](ROADMAP.md#5-таблица-боль--инструмент).
