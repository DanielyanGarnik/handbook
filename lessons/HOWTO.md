# Как писать программы: по шагам, на примере заданий

Это не справочник по Python. Это способ писать программы, когда ты ещё ничего не умеешь —
и, что важнее, когда уже умеешь. Способ один и тот же.

Первое задание разобрано целиком: на нём видно метод. Дальше подсказок становится меньше,
и последний шаг каждый раз твой. Это сделано нарочно.

---

## Главное правило

> **Программа пишется не целиком. Она пишется по одной строке, и после каждой запускается.**

Самая частая ошибка новичка — не синтаксис. Это попытка написать всю программу сразу,
запустить её в первый раз в конце и получить ошибку, про которую непонятно, откуда она взялась.

Если добавлять по строке и запускать после каждой, то ошибка всегда в том, что ты написал
последним. Искать больше негде. Это превращает отладку из гадания в работу.

Ты это уже видел под другим именем: **walking skeleton**. Сначала что-то, что запускается
целиком, потом наращиваем. Там был проект, здесь — программа. Масштаб разный, приём один.

---

## Порядок работы над любым заданием

1. **Прочитать критерии приёмки**, а не только условие. В критериях написано, что именно будет
   проверяться. Условие объясняет задачу, критерии — определяют, что считается сделанным.
2. **Написать одну строку, которая точно работает.** Хоть `print("начало")`.
3. **Запустить.** Да, из-за одной строки.
4. **Добавить один маленький шаг. Запустить.** И так, пока не сойдётся.
5. **Прогнать `check.py`.** Если не сошлось — читать, что он говорит, а не менять код наугад.

Шаг 3 кажется лишним. Он не лишний: он проверяет, что файл вообще запускается, что ты в той
папке и что Python вообще есть на этой машине. Половина «у меня не работает» ловится здесь.

## task01 — разбор целиком

**Задача:** прочитать имя и напечатать приветствие.
**Критерии:** одна строка вида `Привет, ИМЯ!`, ничего лишнего.

### Шаг 1. Что-нибудь, что запускается

Создай файл `task01.py` рядом с `check.py`:

```python
print("начало")
```

Запусти:

```
python task01.py
```

Увидел `начало` — отлично. Теперь точно известно: файл на месте, Python работает, ты в нужной
папке. Это не ерунда, это фундамент.

> Если вместо вывода открылся магазин приложений или написано «Python не найден» — попробуй
> `py -3 task01.py`. На Windows команда `python` иногда перехвачена заглушкой.

### Шаг 2. Научиться читать ввод

```python
name = input()
print(name)
```

Запусти, набери `Ани`, нажми Enter. Программа напечатает `Ани`.

Что здесь произошло: `input()` остановил программу и подождал, пока ты что-то напишешь.
То, что ты написал, он **вернул** — и это значение мы положили в коробочку с именем `name`.
Знак `=` здесь не «равно», а «положи справа в то, что слева».

### Шаг 3. Собрать нужную строку

```python
name = input()
print("Привет, " + name + "!")
```

Запусти, набери `Ани`. Получишь `Привет, Ани!`.

Плюс между строками — это склейка. `"Привет, " + "Ани"` даёт `"Привет, Ани"`. Обрати внимание
на пробел после запятой внутри кавычек: без него получится `Привет,Ани`. Кавычки — это границы
строки, всё внутри них берётся буквально.

### Шаг 4. Проверить

```
python check.py task01
```

Должно быть три зелёных кейса.

### Ловушка, в которую попадают почти все

Естественно хочется написать так:

```python
name = input("Введи имя: ")
```

Так удобнее человеку — видно, чего от него ждут. Но текст `Введи имя: ` тоже печатается,
и попадает в ту же строку, что и ответ. Проверка увидит `Введи имя: Привет, Ани!` вместо
`Привет, Ани!` и не сойдётся.

`check.py` это распознаёт и говорит прямо. Но стоит понять, почему так устроено: программа,
которая печатает лишнее, не годится в конвейер. Её вывод нельзя передать следующей программе
и нельзя проверить автоматически. Поэтому правило: **печатаем только результат**.

## task02 — где ломается интуиция

**Задача:** прочитать два числа и напечатать сумму.

### Шаг 1. Сделай наивно и запусти

```python
first = input()
second = input()
print(first + second)
```

Запусти, введи `2`, потом `3`.

Получишь `23`.

**Остановись здесь.** Это не баг, это самый важный момент задания. `input()` всегда возвращает
**строку** — текст, а не число. Для строк `+` означает «склей», а не «сложи». `"2" + "3"`
честно даёт `"23"`.

Компьютер не угадывает, что ты имел в виду. Тип данных — это не формальность, это то, что
определяет смысл операции.

### Шаг 2. Превратить текст в число

Строку можно попросить стать числом: `int("2")` даёт `2`.

Попробуй сначала на одном значении, запусти, посмотри, что изменилось. Потом на втором.

### Шаг 3. Твой

Собери и прогони `check.py`. Проверь на отрицательных — они есть среди кейсов.

### Если увидишь `ValueError`

```
ValueError: invalid literal for int() with base 10: 'два'
```

Это значит: `int()` попросили превратить в число то, что числом не выглядит. Сообщение даже
показывает, что именно не получилось — `'два'`. Ошибки Python почти всегда говорят правду,
их надо читать, а не пугаться.

## task03 — почему цикл, а не пять print

**Задача:** напечатать пять предметов, каждый с новой строки.

### Шаг 1. Сделай в лоб

```python
print("HDMI-кабель")
print("переходник")
```

Запусти. Работает.

Так можно дописать все пять, и вывод будет правильным. Но посмотри на критерии: список должен
быть **в переменной**. Это не придирка. Завтра предметов станет двадцать, послезавтра они будут
приходить из файла — и пять print придётся переписывать целиком, а цикл не придётся трогать
вообще.

### Шаг 2. Положи список в переменную и посмотри на него

```python
items = ["HDMI-кабель", "переходник", "зарядка", "удлинитель", "мышь"]
print(items)
```

Запусти. Увидишь:

```
['HDMI-кабель', 'переходник', 'зарядка', 'удлинитель', 'мышь']
```

Это весь список одной строкой, со скобками и кавычками. Не то, что нужно, — но полезно увидеть
своими глазами, чем список отличается от его содержимого.

### Шаг 3. Пройти по списку

Цикл читается почти по-русски: «для каждого item в items — сделай вот это».

```python
for item in items:
    print(item)
```

Две вещи, на которых спотыкаются:

- **двоеточие** в конце строки с `for`;
- **отступ** у следующей строки — четыре пробела. Отступ здесь не украшение: именно он
  говорит Python, что `print` находится *внутри* цикла. В других языках для этого фигурные
  скобки, в Python — отступ.

### Шаг 4. Твой

Собери и прогони.

### Если увидишь `IndentationError`

```
IndentationError: expected an indented block
```

После двоеточия Python ждёт строку с отступом, а её нет. Проверь, что строка под `for`
сдвинута вправо.

## task04 — та самая форма

**Задача:** из списка компьютеров напечатать имена только включённых.

Это не просто следующее задание. Это форма, к которой сводятся **все три проекта** вашего курса:

```
список  →  фильтр  →  печать
```

Учёт ПК, Lost&Found, «что задано» — различаются только данные. Если ты сделаешь это задание,
ты сделал скелет своего проекта.

### Шаг 1. Посмотри, из чего состоит список

```python
computers = [
    ("PC-01", "on"),
    ("PC-02", "off"),
]

for pair in computers:
    print(pair)
```

Запусти. Увидишь `('PC-01', 'on')` — каждый элемент здесь не одно значение, а **пара**:
имя и состояние вместе.

### Шаг 2. Разложить пару на две переменные

Python умеет разбирать пару прямо в заголовке цикла:

```python
for name, state in computers:
    print(name, state)
```

Запусти. Теперь `name` и `state` — отдельные переменные, с каждой можно работать.

### Шаг 3. Добавить условие

Нужно печатать не все, а только те, у которых `state` равно `"on"`.

Условие пишется через `if`, и сравнение — это **два знака равенства**: `==`. Один знак `=` —
это «положи», а не «сравни». Это разные вещи, и Python на попытку присвоить внутри `if`
ответит ошибкой.

`if` внутри `for` получает свой отступ — восемь пробелов вместо четырёх. Отступы показывают
вложенность: цикл, внутри него условие, внутри условия действие.

### Шаг 4. Твой

Собери целиком, проверь список из пяти машин, прогони `check.py`.

## Как читать ошибки

Когда программа падает, Python печатает **traceback**. Читать его надо снизу вверх:

```
Traceback (most recent call last):
  File "task03.py", line 2, in <module>
    print(items[5])
IndexError: list index out of range
```

- **последняя строка** — что случилось (`IndexError`, вышли за границы списка);
- **строка выше** — где именно (`task03.py`, строка 2) и какой код это сделал.

Пять ошибок, которые ты увидишь на этой неделе:

| Ошибка | Что значит | Куда смотреть |
|---|---|---|
| `SyntaxError: invalid syntax` | Python не понял строку | пропущено двоеточие, скобка или кавычка — на указанной строке или на строке выше |
| `IndentationError` | сбились отступы | после двоеточия нужен отступ; не смешивай табы и пробелы |
| `NameError: name 'x' is not defined` | используешь то, чего нет | опечатка в имени или переменная создаётся ниже, чем используется |
| `TypeError: can only concatenate str ... to str` | складываешь строку с числом | либо `int()`, либо `str()` — смотря что хотел |
| `ValueError: invalid literal for int()` | `int()` дали не число | проверь, что приходит на вход |

## Когда застрял

По порядку, не перепрыгивая:

1. **Перечитай критерии приёмки.** Половина расхождений — это не ошибка в коде, а невнимательно
   прочитанное условие.
2. **Сузь до одной строки.** Какая именно строка ведёт себя не так, как ты думаешь? Пока
   не знаешь — ты не отлаживаешь, а гадаешь.
3. **Напечатай промежуточное.** `print(name)` посреди кода — это нормальный инструмент,
   а не признак слабости. Посмотри, что реально лежит в переменной, а не что ты думаешь,
   что там лежит. Расхождение между этими двумя — источник большинства ошибок.
4. **Запусти `check.py` ещё раз.** С каждой попыткой подсказка становится конкретнее.
   Попытки не считаются против тебя — это не оценка.
5. **Объясни вслух соседу**, что должно происходить, строка за строкой. Очень часто ошибка
   находится на середине объяснения, и собеседник даже не успевает ничего сказать.
6. **Позови преподавателя.** Пятая попытка подряд без движения — это уже не про внимательность,
   и сидеть над ней в одиночку незачем.

## Что из этого останется

Синтаксис Python забудется и нагуглится. Останется другое:

- программа пишется маленькими шагами, каждый из которых запускается;
- сообщение об ошибке — это подсказка, а не наказание;
- сначала то, что работает целиком, потом то, что работает хорошо;
- прежде чем чинить, надо узнать, что именно сломано.

Это одинаково верно для пяти строк на Python и для системы, которую пишут двести человек.
